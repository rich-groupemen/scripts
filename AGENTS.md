# Instructions

## Development Workflow & Execution
- Always change directory to the correct repository path (`cd <path>`) before executing repository actions or commits.
- Always run local linters and tests, and ensure they pass successfully *before* generating or displaying commit commands.
- When code is ready, break down commits logically into clean, atomic changes with suitable, descriptive commit messages.

## Scratchpads & Documentation Lifecycle
- **Scratch Phase:** For every new script or project, open a scratch file to track progress in real-time. Record all errors encountered, attempted fixes, successes, failures, and any technical notes.
- **Redaction Phase:** Once a script or tool is fully functional and complete, redact and condense the scratch log into a structured, production-ready documentation file for that app or script. Extract key lessons learned and append them to the repository's permanent guidelines for future projects.
